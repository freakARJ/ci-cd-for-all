Day 2 · Inside the CI Server
Your workflow triggered! GitHub provisions a fresh ubuntu-latest virtual machine runner to check out your repository, install Node.js, install packages, run tests, and build your app.

Core Concepts

What it means: Workflows hold jobs (which run in parallel unless ordered via needs:). Jobs hold sequential steps (`uses:` actions or `run:` shell commands).
jobs:
  build:
    needs: test
    runs-on: ubuntu-latest
What it means: GitHub-hosted runners start completely empty. actions/checkout@v4 clones your code; actions/setup-node@v4 installs Node.js.
- uses: actions/checkout@v4
- uses: actions/setup-node@v4
  with:
    node-version: 22

Runner Architecture

Inside ubuntu-latest

  • Fresh VM: Zero leftover files from other runs.
  • actions/checkout@v4: Clones repo into $GITHUB_WORKSPACE.
  • actions/setup-node@v4: Pins exact Node.js v22 runtime.
  • npm ci: Clean deterministic install from lockfile.
  • Fail-fast: Non-zero exit code stops later steps immediately.
